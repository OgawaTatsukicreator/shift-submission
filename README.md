# シフト提出・希望確認システム

Google Apps Script と Google スプレッドシートで動く、従業員ログイン付きの月間シフト希望提出・希望確認・PT申請システムです。

従業員はスマートフォン向けのWeb画面から1か月分のシフト希望を提出し、自分が提出した月間希望とPT申請を確認できます。確定シフトの従業員画面表示は現在の対象外です。

店長・エリア管理者がスプレッドシート上で行う調整・確定処理は関連する管理機能として残していますが、確定結果は従業員向けWeb画面には表示しません。

## ファイル

- `GasApp.html`: GASウェブアプリ用のログイン・初回登録・希望提出・希望確認・PT申請画面
- `Code.gs`: Google Apps Script バックエンド
- `.docx/RDD.md`: 要件定義書
- `.docx/Design.md`: 設計書
- `index.html`, `styles.css`, `app.js`: 旧静的HTML版のファイル。現在のGAS版では基本的に `GasApp.html` を使用する

GAS版は `google.script.run` で `Code.gs` の関数を呼び出すため、旧静的版の `app.js` に `SCRIPT_URL` を設定する必要はありません。

## スプレッドシート構成

現在は1つのスプレッドシートに全データを集約せず、用途別に4つのファイルへ分けます。

| ファイル種別 | 定数 | 主な用途 |
| --- | --- | --- |
| 全体確認用スプレッドシート | `OVERALL_SPREADSHEET_ID` | 確定シフト、変更履歴、全体確認シート |
| DB管理用スプレッドシート | `ADMIN_SPREADSHEET_ID` | エリア、店舗、従業員、所属店舗、管理対象ファイル、ID_DB、パスワードサマリ |
| エリア確認用スプレッドシート | `AREA_SPREADSHEET_ID` | 店長・エリア管理者が調整するエリア別シート |
| シフト提出状況兼PT提出log確認用スプレッドシート | `SUBMISSION_LOG_SPREADSHEET_ID` | シフト希望、PT申請ログ、ログインアカウント、ログインセッション |

`OVERALL_SPREADSHEET_ID`、`AREA_SPREADSHEET_ID`、`SUBMISSION_LOG_SPREADSHEET_ID` は、DB管理用スプレッドシートの `管理対象ファイル` シートを優先して読みます。コード上の定数は、DB側にIDがない場合の予備値です。

## DB管理用スプレッドシート

DB管理用スプレッドシートがマスタです。店舗や従業員が増減した場合は、原則としてコードではなくこのスプレッドシートを更新します。

| シート名 | 用途 |
| --- | --- |
| `エリアマスタ` | エリアID、エリア名、表示順、有効フラグ |
| `店舗マスタ` | 店舗ID、店舗名、短縮名、所属エリア、表示順、有効フラグ |
| `従業員マスタ` | 従業員ID、氏名、主所属、雇用区分、役職、権限、表示順、有効フラグ |
| `従業員店舗設定` | 主所属、兼務、ヘルプ候補、名前選択欄への表示可否 |
| `管理対象ファイル` | 全体確認用、エリア確認用、提出ログ用などのスプレッドシートID |
| `ID_DB` | 管理者が従業員情報を編集し、反映するための作業用シート |
| `従業員パスワードサマリ` | 従業員ID、パスワードハッシュ、更新日時、有効フラグ。ソルトやセッション情報は保存しない |

提出ログ用スプレッドシートには、次の認証用シートも作成されます。

| シート名 | 用途 |
| --- | --- |
| `ログインアカウント` | 従業員ID、パスワードハッシュ、ソルト、登録・更新日時、ログイン失敗回数、ロック期限 |
| `ログインセッション` | ログイントークンのハッシュ、有効期限、最終利用日時、有効フラグ |

### `管理対象ファイル` の例

| 管理単位 | エリアID | 店舗ID | スプレッドシートID | 用途 | 編集権限者 | 有効フラグ |
| --- | --- | --- | --- | --- | --- | --- |
| 全体確認 |  |  | 全体確認用ID | 全体確認・確定シフト | システム管理者 | TRUE |
| エリア確認 |  |  | エリア確認用ID | エリア別シフト調整 | 店長・エリア管理者 | TRUE |
| 提出ログ |  |  | 提出ログ用ID | シフト希望・PT申請ログ | システム管理者 | TRUE |

## GAS連携手順

1. DB管理用、全体確認用、エリア確認用、提出ログ用のスプレッドシートを用意します。
2. `Code.gs` の先頭にある4つのスプレッドシートIDを設定します。
3. Apps Script を開き、`Code.gs` の内容を貼り付けて保存します。
4. Apps Script で HTML ファイルを追加し、ファイル名を `GasApp` にします。
5. `GasApp.html` の内容を貼り付けて保存します。
6. `authorizeOnce()` またはメニューの `初期シート作成` を実行し、必要な権限を承認します。
7. DB管理用スプレッドシートのマスタ各シートに、エリア・店舗・従業員・所属店舗・管理対象ファイルを入力します。
8. 「デプロイ」から「新しいデプロイ」を選び、種類を「ウェブアプリ」にします。
9. 実行ユーザーは「自分」、アクセスできるユーザーは運用に合わせて設定します。
10. 発行されたウェブアプリURLを従業員へ共有します。

## ログインと初回登録

- ログインIDには `従業員マスタ` の `従業員ID` を使用します。
- 初めて利用する従業員は `初めての方` から従業員IDを照合し、本人名を確認してからパスワードを登録します。
- パスワードは平文では保存せず、従業員ごとのソルトを使ったハッシュとして `ログインアカウント` に保存します。
- パスワードを5回連続で確認できなかった場合は、15分間ログインを停止します。
- ログインセッションの有効期限は12時間です。ブラウザのタブを閉じた場合も、次回は再ログインが必要です。
- ログイン後の名前は本人に固定されます。エリアと店舗は主所属を初期表示し、ヘルプ勤務などに合わせて変更できます。
- メイン画面の `パスワード変更` から、現在のパスワードを確認したうえで新しいパスワードへ変更できます。
- 認証の正データは提出ログ用スプレッドシートに保存し、DB管理用スプレッドシートの `従業員パスワードサマリ` へ従業員IDとハッシュを同期します。
- `setupMasterSheets()` の初回実行時、旧DB管理用ファイルにログインアカウントがあり提出ログ用ファイルにない場合は、重複を避けてコピーします。旧セッションは移行せず再ログインとし、旧シートは安全のため自動削除しません。
- 認証用シートとパスワードサマリの閲覧・編集権限は、システム管理者だけに限定してください。

## 利用者別の主な機能

| 利用者 | 機能 |
| --- | --- |
| 従業員 | シフト希望提出、提出済み希望の確認、PT申請 |
| 店長 | エリア確認用シートでのシフト調整、確定反映 |
| エリア管理者 | エリア内の配置確認、ヘルプ調整、確定反映 |
| システム管理者 | マスタ管理、全体確認、提出ログ確認、変更履歴確認 |

## 従業員向けWebアプリの範囲

- `希望提出`: ログイン中の本人名に固定し、月間シフト希望を新規提出または更新する
- `希望確認`: 対象月を指定し、本人の月間希望とPT申請履歴を確認する
- `PT申請`: 通常の月間希望とは別にPT勤務を申請する
- 希望確認は提出ログ用スプレッドシートだけを参照し、全体確認用スプレッドシートの `確定シフト` は読み取らない
- 確定シフトの個人別表示は、確定データと公開ルールが整った段階で追加する将来機能とする

## 入力区分

| 区分 | 内容 |
| --- | --- |
| `勤務可能` | 通常勤務できる日。11:00〜20:00の範囲で開始・終了時間を保存する |
| `休み希望` | 休み希望日 |
| `有給希望` | 有給希望日 |
| `PT` | PT勤務希望またはPT申請。07:00〜22:00の範囲で開始・終了時間を保存する |
| `未入力` | 未申請扱い |

標準勤務時間は `Code.gs` の `DEFAULT_START` と `DEFAULT_END` で管理します。
勤務可能・PTともに開始時間が終了時間と同じ、または終了時間より遅い場合は提出できません。画面とGASの両方で検証します。

## 送信・クリア時の確認

`シフト希望を提出` と `入力をクリア` は、押下後すぐには実行されません。最終確認画面を表示し、確定ボタンを押した場合だけ処理を実行します。

- `提出する`: シフト希望を提出する
- `クリアする`: 入力内容と下書きを削除する
- `キャンセル`: 押下前の画面に戻る

## 受付停止

通常シフト希望の受付を停止する場合は、Apps Script 側の `ACCEPTING` を `false` に変更して再デプロイします。

PT申請は通常シフト希望とは別扱いです。前日まで申請できる運用を前提にしています。
現在のバックエンドではPT申請を管理者用の確定データにも自動反映しますが、従業員画面には申請内容だけを表示します。

## 注意点

- ローカルの `Code.gs` や `GasApp.html` を編集しても、GASエディタには自動反映されません。GAS側へ貼り替えるか、同期ツールを使って反映してください。
- セルの背景色は管理者が見やすくするための表現です。最終的な正データは `確定シフト` シートに保存します。
- `IMPORTRANGE` や `QUERY` による結合は閲覧補助としては使えますが、確定シフトの正データにはしません。
- 従業員向けWebアプリは現時点で確定シフトを表示しません。管理者用の全体確認機能とは表示範囲を分離しています。
